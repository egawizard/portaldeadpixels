## Why Uniswap Official is now the baseline

The live tests showed that hand-built Universal Router / custom direct-pool
transactions could consume more gas than the transaction built by the official
Uniswap app.

V2 therefore calls the official Uniswap Trading API with:

```text
routingPreference: BEST_PRICE
```

The API can choose across supported Uniswap protocols and UniswapX when eligible.

If Uniswap is best, GLITCH uses Uniswap.

If Nordstern or LI.FI produces a better estimated net result, GLITCH uses that
route instead.

## UniswapX

On Robinhood Chain, UniswapX V3 is supported by the official Trading API.

For ERC-20 input trades, a BEST_PRICE quote may return a `DUTCH_V3` route.
The portal then:

1. checks/executes Permit2 approval if needed;
2. asks the wallet for the EIP-712 permit signature;
3. submits the order to `/order`;
4. polls order status;
5. the filler pays the swap execution gas.

Native-ETH UniswapX is intentionally disabled in this V2 because it requires
EIP-7914 / smart-wallet preparation. Native ETH still receives official
Uniswap AMM BEST_PRICE routing.

```text

```

Target:

```json

  "providers": {
    "uniswapOfficial": true
```

but V2 cannot provide the Uniswap baseline comparison.

deviates when another provider offers a better net result.

## Safety

- non-custodial;
- no DEAD PIXELS swap contract in the asset path;
- official Uniswap transactions are generated by the Uniswap API;
- quote/permit data are refreshed after token approval;
- Uniswap API execution is simulated before the unsigned swap transaction is
  returned;
- Nordstern and LI.FI retain their existing direct execution flows;
- start with tiny live swaps after every deployment change.


## V2.1 Robinhood fix

Robinhood Chain (4663) deploys Universal Router **2.1.1** at
`0x8876789976decbfcbbbe364623c63652db8c0904`.

V2 incorrectly forced `x-universal-router-version: 2.0`.
The Uniswap API rejects that version on Robinhood Chain, so the portal could
show `UNISWAP API NOT ACTIVE` even though the API key itself was present.

V2.1 explicitly uses `2.1.1` for `/quote` and execution requests and makes the
health endpoint verify actual Uniswap API connectivity.
